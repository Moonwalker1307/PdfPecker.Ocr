# Contributing to PdfPecker.Ocr

Thanks for helping. Bug reports, small fixes and feature ideas are all welcome. For anything larger than a bug fix,
please open an issue first so we can agree on the approach before you spend time on it.

By contributing you agree that your contributions are licensed under the [MIT license](LICENSE), and to follow the
[code of conduct](CODE_OF_CONDUCT.md). Security problems go through the [security policy](SECURITY.md), not public
issues.

## Reporting a bug

The most useful report is a small image or PDF that shows the problem, the options you passed, the text you expected
and the text you got. For misread text, a crop of the line is often enough. Please leave out anything private: scans
of real paperwork usually hold names, addresses and account numbers, so make a synthetic sample if you can.

## The hard rules: no dependencies, no native code

The NuGet package depends only on the released PdfPecker package. It has its own neural network runtime and runs the
models in C#, and that is the point of the project. A pull request that adds a `PackageReference` to
`src/PdfPecker.Ocr`, a native library, or a call into ONNX Runtime or Tesseract cannot be merged. The package must also
stay trimmable and Native AOT compatible, so no reflection-based code. When the package needs something PdfPecker
cannot do, the change goes to [PdfPecker](https://github.com/Moonwalker1307/PdfPecker) first.

## Building and testing

You need the .NET 10 SDK. The package and tests target `net8.0`, `net9.0` and `net10.0`, and CI runs all three.

```
dotnet build -c Release
dotnet test -c Release --no-build
dotnet test -f net10.0 --filter "FullyQualifiedName~GoldenTests"   # one class, one runtime
```

If you only have one runtime installed, pass `-f net10.0` (or the one you have). [BUILD.md](BUILD.md) and
[TESTING.md](TESTING.md) have the details, and [AGENTS.md](AGENTS.md) the full set of rules the project works by.

Things that will fail the build or CI:

- Warnings are errors, and the analyzers in `src/PdfPecker.Ocr/.globalconfig` check for sealed classes, static
  methods, span-based string handling and culture-independent formatting.
- Every public member needs an XML doc comment.
- **Reference tests** compare the models' outputs with ONNX Runtime's; a kernel change must keep them within 1e-3.
- **Golden tests** (`tests/PdfPecker.Ocr.Tests/Golden/`) compare recognised text and searchable PDFs with checked-in
  baselines. If your change is meant to alter output, regenerate them and say in the pull request which baselines
  changed and why:

  ```
  PDFPECKER_OCR_UPDATE_GOLDEN=1 dotnet test -f net10.0 --filter "FullyQualifiedName~GoldenTests"
  ```

  Please don't regenerate just to make a failing test pass, and a refactor or speed-up should leave every baseline
  unchanged.
- Malformed input may only surface as the exceptions the public API documents. A fix for a crash or hang on bad input
  gets a regression test in `HostileInputTests`, and new handling of untrusted input also needs resource limits and a
  fuzz target (see [fuzz/README.md](fuzz/README.md)).

To check that a change does not slow things down, run `bench/compare-versions.sh <base-ref>`, which benchmarks both
versions in turns on the same machine, and put the numbers in the pull request.

## Code style

- Nullable enabled, file-scoped namespaces, `internal` unless it is part of the public API.
- Classes are `sealed` or `static`, and hot paths use spans and pooled or planned buffers rather than new arrays.
- The model data in `src/PdfPecker.Ocr/Models/` is generated by `tools/ModelBuilder`; change the generator, not its
  output, and keep `THIRD-PARTY-NOTICES.md` in step with it.
- Comments are plain, full sentences that explain why, not what.

## Pull requests

- Branch from the latest `main` and keep a pull request to one change.
- Commit subjects are short sentences without prefixes, e.g. "Fuse hard swish into the depthwise convolution".
- If the change adds or changes a feature, a limitation or a measured figure, update `README.md` too.
- Fill in the pull request template; CI must be green before review.
